## 一、自我介绍

研二在读，做视觉方向的小实验，方向是「少样本条件下的数据增强与预训练对比」。日常一半时间在读论文、一半时间在跑实验表格，导师每周要一次进度。

所以我这个作品是按自己的真实工作流做的：读文献、抄数字、做成表、发周报，来回切 Zotero、Excel、Outlook 能切到手忙脚乱。

---

## 二、作品是什么

**「案头」是一个给研究生用的桌面式工作台：把论文 PDF 拖进去就能提问，答案里的每条结论都带原文角标，点一下跳到原文段落；把答案里的数字一键变成可编辑的数据表和报表，再一键把报表快照发成邮件给导师。**

一句话：文献、数据、邮件在同一个桌面里，不用来回切网页。

## 三、为什么做

我做过一个统计：每周花在「把论文里的数字抄进 Excel 再排版成周报」这件事上，大概两个半小时。抄错一个数是常事，因为原文里那句话我往往只看了半句。

市面上的工具各有各的边界：文献管理器管引文不管数据，AI 聊天工具给结论但不给原文位置，表格工具不知道数是从哪句里来的。我想要的其实很朴素——**每个数字都能点回它的出处**，这样我才敢把它发给导师。

所以做了三件别处没有的事：

1. **摘录和推断分开显示**。回答里引用原文的段落用灰色底 + 左竖线，模型自己的归纳用浅蓝底并挂一个「推断」标签。我不想在读结论的时候分不清哪句是论文说的、哪句是模型说的。
2. **角标点开就是原文**。点回答里的 [1]，右边的证据栏会滚到对应段落并高亮，同时显示页码、段落号和相似度分数，不用去 PDF 里翻。
3. **答案直接变表**。回答里检出的数值会列出「指标 / 数值 / 单位 / 来源」四列，一键生成数据表，然后表格视图里出指标卡和柱线图，再导出 XLSX 或者直接发邮件。中间不手动誊抄。

## 四、怎么用（评委照着点，五步）

1. **打开链接，首屏就有东西**：左边是 3 篇示例论文，中间左边是「文献问答」，右边是「数据表」，底部流水线显示读 / 写 / 发的进度。不用注册，不用配 key。
2. **提问**：在文献问答窗口底部的输入框打一句话，比如「这几篇在预处理上的差异是什么」，按回车。回答会逐字流出来，每条结论后面有角标。点角标，右边证据栏会跳到原文段落并高亮。也可以直接把自己的 PDF 拖到页面任意位置，浏览器本地解析，不上传。
3. **建表**：回答下方点「带着答案去建表」，数值会变成一张新表，问答窗口自动收到左半屏、数据表落到右半屏并排对照。
4. **出报表**：数据表右上角切到「报表」视图，看三张指标卡（样本数 / 组间差异 / 显著列）和柱线组合图；列头右侧的小三角可以看该列的均值、中位数、缺失率。
5. **发出去**：点「导出报表」，选 XLSX，勾上「导出后邮件发送」，右侧弹出邮件抽屉——模板、变量（未填的会标橙）、报表快照附件都在那儿，三项检查清单全绿后点发送，成功后顶部一条绿线收束，左栏「发」里能看到发送记录。

想试真实发信的话，设置里填 EmailJS 的三个参数；不填就是本地模拟发送，界面会写明「本地模拟发送，不经过外部服务」，不会假装信已经发出去了。

## 五、用 Qoder 做出来的过程

整体思路是我自己定的：先画信息架构（一条「读 → 写 → 发」的流水线 + 三个可拖拽工作面），再定设计令牌（纸白底 + 单一学术蓝 + 三档语义色 + 衬线标题配等宽数字），最后才动手写。

具体分工是这样的：

**交给 Qoder 的部分**

- 整个项目骨架：Vite + React + TypeScript + Tailwind + Zustand 的初始化、目录结构、设计令牌文件。
- 三个核心工作面的大段实现：文献问答窗口（分块渲染、角标联动证据栏、流式输出）、数据表窗口（可编辑表格、列统计浮层、报表视图与 ECharts 图表）、邮件抽屉（变量 chip、检查清单、附件卡）。
- 窗口管理器：拖拽、落位预览、四分屏 / 三分栏吸附、最小化到底栏、置顶、位置持久化。
- 检索链路：pdf.js 解析 → 段落分块（带页码与段落号）→ minisearch 中文二元分词检索 → 命中打分。
- 数值抽取：从回答段落里识别「指标 / 数值 / 单位」，生成表格初始行。
- 导出：SheetJS 写 XLSX（数值列保持数值类型）、CSV 带 BOM、PDF 走浏览器打印避免中文字形缺失。
- 命令面板（`⌘K`）、阶段化左栏、底部流水线状态条、拖拽投放 PDF 的全屏提示。

**我自己改和定的地方**

- **信息架构推倒重来一次**。第一版是常规的「顶栏 + 图标栏 + 列表栏 + 画布 + 右侧检查器」，我自己看着觉得像十年前的软件，推倒重做成现在这种「一条流水线 + 阶段化左栏 + 可拖拽工作面 + 浮层检查器」。
- **视觉语言**。把整体从「白底蓝字」往专业工具的密度上推：字号压到 22/16/14/12 四档，数字统一等宽字体，表格斑马纹和表头灰底对齐论文排版，阴影只留一档。
- **摘录与推断的视觉区分**。这是我和 Qoder 讨论后自己定的规则：原文摘录用灰底 + 左竖线、模型推断用浅蓝底 + 一个「推断」小标签 + 一行「模型归纳，非原文」的说明。后来又补了一句：本地模式下模型返回的文本要过一遍 emoji 过滤，全站不允许出现 emoji。
- **引用联动的交互细节**。角标点开后要滚动到对应证据并高亮 1 秒多，同一条证据的多个角标要合并，证据卡要显示页码、段落号和相似度分数——这些是实现完我实际点了一遍才发现缺的。
- **数值抽取的清洗规则**。第一版抽出来的指标名有「策略组合取得」「0% 用于混合」这种，我加了首尾虚词剥离和纯数字兜底，才变成能看的「样本规模」「线性探测准确率」。
- **邮件变量改成行内编辑**。原本用 `prompt()` 弹窗，体验很糙，改成点 chip 就地出现输入框；导出时把「本周样本数 / 数据集名称 / 本周结论 / 日期」自动填好，只留「导师姓名」给用户填，检查清单三项全绿才允许发送。
- **零配置兜底**。这是我自己定的硬要求：任何一步都不能让评委去申请 key。所有外部能力（在线模型、真实发信）都做成设置里的可选项，默认走本地检索 + 本地模拟发送，界面上明确标注当前模式，不假装调用了模型。

## 补充说明（诚实起见）

- 邮件默认是**本地模拟发送**，只写发送记录并支持导出 .eml，没有真的发出去；要真实发信请在设置里填 EmailJS。
- 在线模型（DashScope / qwen-plus）需要自己填 key，没填时检索与归纳都在浏览器本地完成，界面右上角一直显示当前是「体验模式 · 本地检索」。
- PDF 走 pdf.js 文本层，扫描件没有 OCR 层，解析不出正文时会明确标成失败并给原因，不会假装解析成功。
